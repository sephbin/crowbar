# Bell Curve GURPS

Andrew's personal variant of GURPS 4e for Ultima Thule: GURPS rules and costs (×10), every roll resolved on the 3d6 curve and shown as a d100 percentage. Not distributed. Paths below are relative to this folder.

## Files
- `engine.js`: the rules, used by both the builder and the tools: 3d6 curve and d100 display, skill and attribute costs, the GCS trait-cost algorithm (modifiers, self-control, frequency, the −80% cap, round up), features (attribute, skill, spell and DR bonuses, conditional modifiers), prerequisites, techniques, weapons, hit locations and injury. Change rules here only.
- `index.html`: builder, sheet and roller. Loads `engine.js` and `data/library.js`. Saves to localStorage and to character JSON (open, save, copy json). Sections sit in tabs like the BRP sheets: base (name, check, templates, attributes), traits, combat (dodge, damage, attacks), skills, magic, kit, notes. Tapping a skill, spell, attribute, Dodge or attack opens the roller as a modal (attack modes, hit locations, circumstances, situation, d100 roll, injury). Its rules tab shows a paraphrased description (from `data/descriptions.js`) above the library data: attribute and difficulty, defaults, prerequisites, technique parent and maximum, spell stats, weapon modes, next-step cost, page reference. The page opens read-only (every load): steppers, remove and add controls, modifier panels and inputs are hidden (`body.view`; editing controls carry class `ed`, their read-only text class `vw`), and the header's edit button shows them. Rolling works in both modes. Tapping a trait opens the same modal on its rules (cost, modifiers, page). When the page is served by the crowbar server, the rules tab also shows the book text and supplement text for the skill, spell or trait, and the text of each modifier on a trait, from `/api/booktext` (server.js, reading the gitignored `rules/library-with-text.json`); elsewhere those sections stay hidden. Rolls show as percentages only; GURPS levels, relative levels and 3d6 equivalents are hidden unless the header's debug toggle is on (elements with class `g`). Tab and debug state are per browser (localStorage `bellcurve-ui`). The examples menu fetches `characters/*.json`, so it needs http (GitHub Pages, or `npx serve ..` from this folder's parent); everything else also works from `file://`.
- Pickers: every add control (trait, skill, spell, equipment, template) and every free-text specialty in the profession dialog opens the chooser panel (`chooser()` in `index.html`): a search box, category chips and a list, with typed text allowed where the list is open-ended. A skill that needs a specialty asks for it in a second chooser. Adding a spell checks its spell prerequisites (`BC.spellPaths` in `engine.js`) and offers to learn them too, with a choice of path where there are several. `data/picks.js` is hand-authored (not generated): suggestion lists for specialties (languages, monster types, Hidden Lore subjects, instruments and so on), keyed by skill name or by the profession data's `ask` word.
- Profession dialog: a skill with a specialty can be taken again for another specialty (a new choice appears below while the group has room); options already taken, in the same dialog or fixed by the profession, are disabled (left out of the "previous traits" lists); options the sheet already has are greyed (traits) or flagged as raising the existing skill or spell. The name, concept and notes fields are read-only in the view; tapping one turns editing on so the phone keyboard opens.
- Page comments: `index.html` loads `annotate/annotate.js` (repo root). The round button at the bottom right is comment mode; comments go to the crowbar server when the page is served by it, else stay in the browser (export from the list panel). Agents read them with `node annotate/cli.mjs list` (see `annotate/README.md`, skill `page-comments`).
- `data/library.json`, `data/library.js`: generated. Do not edit.
- `data/src/`: hand-authored data merged into the library: `house-rules.json` (Backstabber, Sneak Attack), `circumstances.json` (suggested GM values per skill), `natural.json` (punch and kick, B271).
- `data/src/modifier-sets.json`: the standard modifier sets that skill and spell entries point to (equipment B345, cultural familiarity B23, language B24, physiology B181, Magic's long-distance table M14), with paraphrased labels and the page's values; built into the library as `modsets`. With the local book text, the roller adds a skill's or spell's own "Modifiers:" items and the sets it names as dotted circumstance chips (from `rollMods`, parsed by `rules/library_text.mjs`; items for the character's own traits are left out, since trait bonuses already apply).
- `data/src/descriptions.json`: paraphrased skill and spell descriptions for the rules tab, keyed by library name (`"Name (Spec)"` wins over `"Name"`). `node tools/build_desc.mjs` checks every key against the library and writes `data/descriptions.js`. Write them from the book text in `rules/pages/`, in your own words, never copied: the repo is public. So far: every skill and spell Oskar and Brock use, plus Crossbow.
- `rules/`: gitignored. The GURPS PDFs (copyrighted) and their extracted text. Copy `Basic Set - Characters.pdf`, `Basic Set - Campaigns.pdf` and `Magic.pdf` from `\\sanguinecrow\Andrew\GURPS\GURPS 4e` (more books there: Martial Arts, Thaumatology, Fantasy, Low-Tech, Dungeon Fantasy and others), then `node tools/extract_rules.mjs` writes `rules/pages/B222.txt` and so on, named by book page. Add a book to `BOOKS` in that script with its PDF-to-book page offset. `Powers.pdf`, `Martial Arts.pdf` and `Horror.pdf` are also copied there, plus the books GCS cites for traits and modifiers: Psionic Powers, Supers, Reign of Steel - Will to Live, Martial Arts - Gladiators, Gun Fu, Ultra-Tech, High-Tech, Banestorm, Power Ups 2-4 and Dungeon Fantasy 04 and 09. The local book-text tools in `rules/` append their text to the matching Basic Set and Magic entries as supplements, each labelled with its source; a book missing from `rules/` is skipped. Not on the share: Pyramid (PY), Furries (FUR), FFWF, Power-Ups 6, GURPS Lite, Discworld and the Dungeon Fantasy RPG books.
- `characters/*.json`: characters. `oskar-penn.json` is the reference build; `brock-underhill.json` is the badger necromancer with a ghost goat familiar (validates; the goat is homebrew, see its notes).
- `tools/gcs_convert.mjs`: rebuilds the library from a GCS master library checkout.
- `tools/bc_check.mjs`: validator. `tools/bc_find.mjs`: library search. `tools/bc_selftest.mjs`: maths and cost tests.

## Commands
```
node tools/bc_selftest.mjs                     # must say "all passed"
node tools/bc_check.mjs characters/*.json -q   # ERROR/WARN lines with page refs; exit 1 on errors
node tools/bc_find.mjs "magery|ally" traits    # search; add --full for the raw record
git clone --depth 1 https://github.com/richardwilkes/gcs_master_library <dir>
node tools/gcs_convert.mjs <dir>               # rebuild data/library.*
```
On Windows the clone fails on some long paths (Template Toolkit, Discworld, Pyramid). The books used here (Basic Set, Magic, Fantasy races) check out fine. Re-run the self-test after a rebuild: it compares trait costs with the costs GCS computed for every template trait.

## Library contents
Basic Set skills, techniques and traits; Magic skills and spells (not Ritual Magic); Basic Set and Magic equipment; traits, skills and spells from the other books that hold professions (Martial Arts, Powers, Power-Ups, Action, Monster Hunters, Horror, Fantasy, Banestorm, Supers, Psionics, Mysteries, Space, Bio-Tech, Infinite Worlds, High-Tech, Ultra-Tech, Gun Fu, Thaumatology, Reign of Steel, Solar Patrol and Dungeon Fantasy 1, 3, 4; the Basic Set comes first, so a plain name finds its Basic Set record); racial and meta-trait templates (below); the general enhancements and limitations (B101-B117) as `modifiers`. Any trait can take a general modifier; the trait's own `mods` are matched first. The GCS library is MPL 2.0; credit it if anything here is shared. To add a book, add its files to `SOURCES` in `tools/gcs_convert.mjs`.

## Professions and templates
- `lib.professions` (from `data/src/professions.json`): about 165 character templates from 25 books (Dungeon Fantasy 1, 4, 9, 12, 14, 15; Action 1; Fantasy; Martial Arts; Horror; Monster Hunters 1 and 4; Banestorm; Psis; Thaumatology and Urban Magics; Bio-Tech; Space; Supers; Mysteries; Locations, Underground Adventures, Solar Patrol and more). Names, costs and choice rules only (costs ×10), parsed from the books by local tools; GCS's profession files are not used because they differ from the books (DF Barbarian, Basic Speed) and keep their choices in container names only.
- A character records `"profession": { "name", "book", "picks" }`; `BC.profStamp` puts the profession's traits, skills, spells and attribute points on the sheet and `unstampFrom` in `index.html` takes them off. Schema: groups of kind `fixed`, `points` (spend n) or `count` (take n); options of type trait, attr, skill, spell, note, raise (points on a skill already taken), group and bundle. A `points` group with `open` text and no options is an open pool (a lens, "25 points in Holy abilities"). A skill with specialties (`choices`) can be picked again for another specialty.
- Status per template: complete (the parse totals the book's points, every clause read) or `incomplete` (at least half of the book's points parsed, never over: the unread points are one open pool, flagged in the dialog). A template that overshoots, or reads under half, is left out. Races, monsters and fixed characters in the same books are left out of `professions`.
- Local tools (`rules/` is gitignored): `tpl_extract.py` (template pages of each book from the share, by page blocks), `stream_templates.mjs` (the same from `stream.py`'s line streams; used for Fantasy and Banestorm, whose pages mix sidebars into the columns), `df_extract.py` (DF1, 4, 12, 14), then `df_professions.mjs` parses everything into `data/src/professions.json` and writes `rules/professions-report.json`, `rules/professions-all.json` (every template found, with what keeps it out). `prof_show.mjs <Name> [BOOK]` prints a template's parse for checking against the book. Rebuild the library afterwards with `gcs_convert.mjs`.
- Not parsed yet: DF9's summoner powers and spell tables (the four summoners are incomplete), lenses as selectable templates (a lens is an open pool), Supers' 500-point power templates, Reign of Steel's robots, and about 60 older-layout professions with unusual wording (Space, Mysteries, Infinite Worlds, Lands Out of Time, parts of Banestorm and Fantasy).
- `lib.templates` (racial and meta-trait templates, no choices): Basic Set, Fantasy, Magic, Dungeon Fantasy races, Banestorm, Bio-Tech, Ultra-Tech, Horror, Lands Out of Time, Reign of Steel, Fantasy Folk elves, goblins and kobolds. A container's own percentage modifier (Power Modifier -10%) applies to every trait in it (`container: true` on the instance's modifier); a modifier with `perTrait` is charged per level of the trait (GCS `use_level_from_trait`).

**Lenses.** `lib.lenses` (26: Action 1, Monster Hunters 1, DF15) come from `rules/df_professions.mjs` (pages by `rules/tpl_extract.py`, into `rules/lens/`). A lens has the template shape plus `plus` (a "+125" lens is added to the profession; a plain one takes the place of the profession's `lens: true` pool, or is added when there is none). A character records `profession.lens = {name, book}`; `profEffective(prof, lens)` lays its groups over the profession (ids get an `L` prefix so picks share one map). 23 total their book points. DF15 Adept, Priest and Psi are incomplete: their "Special Abilities and Spells" packages need the summoner powers (DF9) and the psi lists. Champion, Avenger/Atoner, Operative and Philanthropist are built by hand in the parser (their wording is one-off). Not surveyed: Monster Hunters 4 and Martial Arts cinematic lenses, Banestorm Mystic lenses.

## Character JSON
```
{
  "format": "bellcurve-character", "version": 1,
  "name": "...", "concept": "...", "budget": 1500, "notes": "...",
  "options": { "backstabber": "all" | "melee" },
  "templates": ["Halfling", { "name": "Badger-folk", "custom": true, "attributes": {"ST": 200}, "traits": [ ... ] }],
  "attributes": { "ST": 0, "DX": 0, "IQ": 0, "HT": 0, "Will": 0, "Per": 0, "HP": 0, "FP": 0, "Speed": 0, "Move": 0 },
  "traits": [ { "name": "Greed", "cr": 12, "points": -150 },
              { "name": "Silence", "levels": 1, "points": 50 },
              { "name": "Ally", "notes": "who", "frequency": 15, "modifiers": ["100% of your starting points", "Summonable"], "points": 300, "character": { ...ally sheet... } } ],
  "skills": [ { "name": "Thrown Weapon", "spec": "Knife", "points": 40 } ],
  "spells": [ { "name": "Death Vision", "points": 10 } ],
  "tl": 3, "settled": false,
  "equipment": [ { "name": "Large Knife", "qty": 2 }, { "name": "Crossbow", "st": 9, "label": "Light crossbow (ST 9)" }, { "name": "Leather Armor", "worn": true },
                 { "name": "Broadsword", "quality": "fine" }, { "name": "Medium Shield" }, { "name": "Tent, 2-Man", "carried": false }, { "name": "5 pt Powerstone", "free": true } ]
}
```
- Attribute values are points spent (×10), not levels. Skill, spell and trait `points` are ×10.
- Trait `points` is the declared cost; the validator recomputes it and reports a mismatch. The builder keeps it in step.
- `"templateRemoved": [{ "template": "Badger-folk", "trait": "Stubbornness" }]` takes a trait off a template for this character only (a removed disadvantage costs its points back). The template is left unchanged, so the builder lists the trait as removed with a "put back" button; the validator reports each removal as ok. Use the trait's name with its notes in brackets when the template gives it notes.
- Skill and spell points can be any number (spells from 10): levels interpolate between the 10-point steps. In the builder, + and − on a skill or spell buy or sell the fewest points that move the roll by 1%.
- Modifiers are named as in the library. Where two share a name, use the label `"Name (adj)"`, e.g. `"People Affected (x1)"`.
- General enhancements and limitations (`node tools/bc_find.mjs <name> modifiers`) go in the same list, as a name or an object: `{ "name": "Area Effect", "levels": 2 }` (4 yd), `{ "name": "Limited Use", "notes": "Once per day" }` (notes pick a variant, matched from the start), `{ "name": "Sense-Based", "adj": "+150%" }` (a value picks the variant with that value). An `adj` that matches no variant sets the value by hand (Cone width, Cyclic cycles) and the validator reports it. The validator warns on combinations the book forbids or requires (Aura needs Melee Attack (Reach C), Drifting needs Delay or Persistent, one penetration modifier, and so on), and on Contact Agent or Blood Agent with Area Effect or Cone, which become +150% and +100% enhancements (B110-B111). GCS lists only the limitation value for Contact Agent, so set `"adj": "+150%"` there.
- Techniques take their parent skill as the specialization: `{ "name": "Arm Lock", "spec": "Judo" }`.
- An ally's sheet is built on its share of the owner's budget, taken from the point-total modifier.
- Equipment (Andrew's ruling: money is not scaled by ×10; B27 wealth as written):
  - `tl` is the campaign TL. Starting wealth is the B27 amount for it times the Wealth trait's multiplier (B25; Multimillionaire N is 100×10^N). Item costs over it are an ERROR; with no `tl` the validator warns and skips the check. Allies use the owner's `tl`. Items above the campaign TL double in price per TL (B27).
  - `"settled": true` limits gear to 20% of starting wealth (B26). The default treats the character as a wanderer who can spend all of it.
  - `quality`: cheap, good, fine or very fine for melee and thrown weapons, arrows and bolts (B274; prices depend on whether the campaign TL is 6 or less, and blades below TL3 get no damage bonus, B275); good or fine for bows (B277); good, fine or very fine for firearms (B280); basic, good or fine for other gear (B345, approximate prices). Armour, shields and Magic items have none.
  - `"carried": false` keeps an item owned (it still costs money) but at home: no weight, DR, DB or attacks. `"free": true` means it wasn't bought from starting wealth (loot, Signature Gear). `"worn": false` takes armour off or puts a shield away.
  - Carried weight against Basic Lift (Lifting ST counts) sets encumbrance (B17): Move and Dodge drop, Climbing, Stealth, Judo and Karate take the level, Swimming twice it, and fencing weapons take it on attacks and parries (B208).
  - Armour (B286): layers on one location add their DR when every inner layer is flexible and concealable (GCS notes, which match the book's tables); an extra layer anywhere but the head gives -1 DX, applied after Basic Speed. Other layering is an ERROR. Split DR is shown, not rolled: mail is 2 lower against crushing, suits' burning-only DR, breastplates front only (DR from behind shown), sandals sole only. The foot is a hit location (-4, as a hand, B399).
  - Parry and Block are 3 + half the skill, fractions dropped (B375-B376), plus the weapon's modifier and trait bonuses. A ready shield's DB is a roller chip on Dodge, Parry and Block (front or shield side). Boots add to kicks; carried kits are roller chips on their skill.
  - Spell energy is the cost after high skill (M8). The validator warns when it is more than FP plus the largest carried Powerstone (only one at a time, M69).

## AI build workflow
1. Read the description. List every trait, skill, spell, item and template it implies.
2. Look each one up with `node tools/bc_find.mjs`. Use the library's name, cost, modifiers and specializations. Never write a stat from memory. Where `rules/library-with-text.json` exists (local only), add `--text` to read the book and supplement text for each chosen trait: check its limits, incompatibilities and GM-permission notes before using it. Costs still come from the library; never copy the book text into a character or the repo. If something is not in the library, keep it out of the library-backed fields, put it in `notes` and flag it for Andrew. A custom template (`"custom": true`) is fine for a homebrew race when its traits are library traits.
3. Write `characters/<slug>.json`.
4. Run `node tools/bc_check.mjs characters/<slug>.json`. Fix every ERROR. Read every WARN and fix it or record the ruling in `notes`.
5. Report the point breakdown and any design problems with numbers. Open the file in the builder (open, or the examples menu after adding it there) to play it.

## House rules (label them as house rules wherever they appear)
- Backstabber (150): against an unaware target, hit-location penalties are halved (eye −4.5). `options.backstabber` set to `"melee"` limits it to melee attacks; the default covers ranged too.
- Sneak Attack (50 per level, max 3 in the data; cap of 2 or 3 is undecided): +1d injury per level against an unaware target, added after the location multiplier.
- Unaware target: no defence roll.
- Throat cut as impaling to the vitals at the neck's −5: not implemented (undecided).

## Known gaps
- Damage types outside imp, pi−, pi, cut, cr use ×1 at every location; the roller says so.
- Not modelled: buying a skill up from a skill default (the defaulted level is used as a floor), wildcard skill cost (costed as very hard, with a warning), attribute cost reductions, ST bonuses for striking only (listed as warnings), Brawling's damage bonus, item damage and breakage, Signature Gear points, DR on the face and groin (no roller location).
- Item book text (local only): 400 of 404 Basic Set items and every Magic item have text. Table rows are rebuilt into the table's own columns from the merged cells the PDF gives (`COLS` in `rules/library_text.mjs`); 19 heavy weapons, helmet add-ons and similar rows don't parse and show as one line. Missing: the two atlatls (not in the extracted text), ICW Integral and the Reich sniper rifle (GCS-only names).
- `script_prereq` prerequisites (4 in the library) are not evaluated.
- Trait weapons (Strikers, Claws, Teeth, Hooves, Innate Attacks) are listed as natural attacks with GCS's damage, including +1 per die and per-level dice; a trait's punch or kick replaces the plain one. Afflictions and Binding are not listed (no injury). Quadrupeds still show the plain punch.
